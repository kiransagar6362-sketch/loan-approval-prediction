## Project Overview

LoanLens predicts whether a loan application is likely to be approved using a machine learning model trained on historical application data. It exposes a clean, responsive web interface where loan officers can enter applicant details and instantly receive:

- An **approval probability gauge** (0–100%)
- A **plain-language risk factor breakdown** (credit history, repayment load, loan size, income)
- **"What-if" suggestions** — actions that would meaningfully improve the applicant's chance
- A **model performance dashboard** with ROC curves, confusion matrix, and feature importance
- A **data insights page** with EDA charts

Gender and marital status are **intentionally excluded** from the model inputs (fairness by design). They are retained in the dataset only for a post-hoc fairness audit.

## Features

| Area | Detail |
|---|---|
| **Data** | 1,200 synthetic applications; realistic missing values; same schema as the Kaggle *Dream Housing Finance* dataset |
| **EDA** | 6 charts: outcome balance, approval by credit history, income distribution, approval by category, correlation matrix, missing-value heatmap |
| **Feature engineering** | Total income, log-total-income, log-loan-amount, monthly EMI, EMI-to-income ratio, loan-to-annual-income multiple |
| **Preprocessing** | Median imputation for numeric, most-frequent for categorical/binary, StandardScaler, OneHotEncoder — all inside a `Pipeline` to prevent data leakage |
| **Model selection** | 4 candidates (Logistic Regression, Decision Tree, Random Forest, Gradient Boosting) tuned with 5-fold stratified CV + GridSearchCV |
| **Evaluation** | Accuracy, precision, recall, F1, ROC-AUC, confusion matrix, permutation feature importance, gender fairness audit |
| **Web app** | Responsive Flask UI; approval-probability SVG gauge; structured risk factors; what-if improvements; mobile-friendly layout |
| **JSON API** | `POST /api/predict`, `GET /api/metrics` |
| **Fairness** | Gender & marital status excluded from model inputs; post-hoc approval-rate audit by gender saved to `metrics.json` |

## Quick Start

```bash
# 1. Create and activate a virtual environment
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux

# 2. Install dependencies
pip install -r requirements.txt

# 3. (Optional) Regenerate the dataset and retrain — not required, model is already saved
python generate_dataset.py
python train_model.py

# 4. Launch the web app
python app.py
# Open http://127.0.0.1:5000 in your browser
```

> The repository already contains a trained model (`models/loan_model.joblib`) and pre-generated figures, so `python app.py` works immediately without retraining.  
> Re-run `train_model.py` if you use a different scikit-learn version than the one that saved the model.

## Dataset

`data/loan_data.csv` uses the same schema as the popular Kaggle *Loan Approval Prediction* (Dream Housing Finance) dataset:

| Column | Type | Description |
|---|---|---|
| `Loan_ID` | string | Unique application identifier |
| `Gender` | categorical | Male / Female — **not used as model input** |
| `Married` | categorical | Yes / No — **not used as model input** |
| `Dependents` | categorical | 0, 1, 2, 3+ |
| `Education` | categorical | Graduate / Not Graduate |
| `Self_Employed` | categorical | Yes / No |
| `ApplicantIncome` | numeric | Monthly income of applicant (INR) |
| `CoapplicantIncome` | numeric | Monthly income of co-applicant (INR) |
| `LoanAmount` | numeric | Requested loan amount (INR thousands) |
| `Loan_Amount_Term` | numeric | Repayment term in months |
| `Credit_History` | binary | 1 = meets guidelines, 0 = does not |
| `Property_Area` | categorical | Urban / Semiurban / Rural |
| `Loan_Status` | binary | **Target** — Y (approved) / N (rejected) |

> **Note:** The dataset included here is **synthetic**. It was generated by `generate_dataset.py` (seeded, reproducible) because the project was built without internet access. It faithfully mimics the real dataset's schema, class balance (≈74% approval), and realistic missing-value pattern. All metrics describe this synthetic data only.  
> To use the real Kaggle dataset: download it, save as `data/loan_data.csv` with matching column names, and run `python train_model.py`.

| Model | CV ROC-AUC | Accuracy | Precision | Recall | F1 | Test ROC-AUC |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| Logistic Regression | 0.787 | 0.858 | 0.849 | 0.983 | 0.911 | 0.826 |
| Decision Tree | 0.767 | 0.833 | 0.855 | 0.932 | 0.892 | 0.791 |
| **Random Forest (selected)** | **0.792** | **0.858** | **0.849** | **0.983** | **0.911** | **0.814** |
| Gradient Boosting | 0.779 | 0.858 | 0.856 | 0.972 | 0.910 | 0.772 |

**Random Forest** was selected for deployment (best cross-validated ROC-AUC combined with equal test-set F1).

| Applicant Income | 0.030 |

Credit history is by far the strongest driver of approval decisions. See `Loan_Approval_Project_Report.docx` for the full analysis.

## API Reference

### `POST /api/predict`

Predicts approval probability for a single application.

**Request body (JSON):**
```json
{
  "Dependents": "0",
  "Education": "Graduate",
  "Self_Employed": "No",
  "ApplicantIncome": 7200,
  "CoapplicantIncome": 2500,
  "LoanAmount": 150,
  "Loan_Amount_Term": 360,
  "Credit_History": 1,
  "Property_Area": "Semiurban"
}
```

**Example (curl):**
```bash
curl -X POST http://127.0.0.1:5000/api/predict \
  -H "Content-Type: application/json" \
  -d '{"Dependents":"0","Education":"Graduate","Self_Employed":"No",
       "ApplicantIncome":7200,"CoapplicantIncome":2500,"LoanAmount":150,
       "Loan_Amount_Term":360,"Credit_History":1,"Property_Area":"Semiurban"}'
```

**Response fields:**

| Field | Description |
|---|---|
| `approved` | `true` / `false` (probability ≥ 0.5 threshold) |
| `probability` | Approval probability [0.0–1.0] |
| `factors` | Array of risk factor objects with `name`, `value`, `status`, `note` |
| `what_if` | Up to 3 suggestions that would raise probability by ≥ 3 pp |
| `summary` | `emi`, `emi_ratio`, `loan_to_income`, `total_income` |
| `caution` | Warning string if the application is more extreme than 99% of training data |

### `GET /api/metrics`

Returns the full `metrics.json` object: model selection, test metrics, confusion matrix, feature importance, fairness audit, and dataset statistics.

## Limitations

- All metrics are measured on **synthetic data** — validate on real historical applications before any production use.
- The model is a **decision-support tool**, not an automated lending decision. An underwriter should review all outputs.
- The class is **imbalanced** (~74% approvals). Recall for rejected applications (61%) is lower than for approvals (98%). Adjust `THRESHOLD` in `app.py` to trade off false-positive vs false-negative risk according to the lender's risk appetite.
- The EMI calculation uses **principal ÷ term** (no interest), consistent with the public dataset. Real EMI would include interest.
- The model was trained without `Gender` or `Married` — this is a deliberate fairness choice. The post-hoc gender audit in `metrics.json` shows predicted approval rates within 5 pp of actual rates for both groups.
